## 0. 인테이크 — 생성 전 확인 질문 (필수, 폴더 생성보다 먼저)

새 프로젝트 시작 지시를 받으면 **폴더를 만들기 전에** 아래 8그룹 36문항을 확인한다.
**모든 문항에 기본값이 있다** — 답이 없으면 기본값으로 진행하고, 기본값을 적용한 항목은 INTAKE.md에 `(기본값)`으로 표기한다.

**질문 방식**: 34개를 한 번에 묻지 않는다. `AskUserQuestion`으로 **그룹 단위 4~5라운드**로 묶어 묻고, 라운드마다 답을 INTAKE.md에 즉시 기록한다. 사용자가 "기본값으로 진행"이라고 하면 남은 라운드를 생략하고 전부 기본값으로 채운 뒤 INTAKE.md를 보여주고 확인받는다.

### G. 문안 뱅크 연동

`_shared/bank/`는 여러 사업에서 반복되는 제안서 문안을 모아둔 공용 자산이다.
연동하지 않으면 매 사업마다 처음부터 다시 쓰게 된다.

| # | 확인 항목 | 기본값 | 반영처 |
|---|---|---|---|
| G1 | 문안 뱅크(`_shared/bank/`) 연동 여부 | 연동 | 연동 안 하면 이하 생략 (그래도 사업 종료 시 환류는 별도 판단) |
| G2 | 뱅크매핑 작성 시점 | B2(요구사항 ID 구조화) 직후 | `00_context/뱅크매핑.md` |

**G1=연동일 때 절차** — 요구사항 xlsx가 나온 직후(B2 다음) 수행한다.

1. 요구사항 ID마다 `_shared/bank/_색인_주제.md`에서 대응하는 주제코드를 찾는다
   (매칭되는 게 없으면 `—`로 비워 둔다)
2. 그 코드의 뱅크 상태(L3 있음 / L1만 / 없음)를 `_색인_주제.md`에서 확인해 적는다
3. `00_context/뱅크매핑.md`에 표로 기록한다 (§3 템플릿)
4. `python3 _shared/lib/bank/pull.py --bank _shared/bank --mapping 00_context/뱅크매핑.md --out 10_work/스펙_초안_<날짜>.md`로
   초안을 뽑아 스펙 작성의 출발점으로 삼는다
5. "없음"으로 남은 항목이 이 사업의 실제 집필 부담이자, 종료 시 환류 후보다

### H. 참고 제안서 (기존 제안서 재사용) ★

**기존 제안서는 회사 표준이다.** 착수 시 반드시 확인한다.

- **H1. 같은 도메인 참고 제안서가 있는가** — `_shared/templates/참고제안서/` 확인
- **H2. 그 제안서에 「제안요구사항 수용 조견표」가 있는가**
  → 있으면 `_shared/lib/bank/xref.py`로 요구사항 코드 경유 교차분석이 가능하다
  → 없으면 목차 기반 수동 대조로 내려간다
- **H3. 판형·마스터 계보가 같은가** (`slide_width/height`, 앞 5개 레이아웃 이름)
  → 같으면 **면 단위 통째 이식**이 가능하다(크롬은 우리 것으로 자동 교체)
- **H4. 코퍼스 추출본이 뱅크에 있는가** — `_shared/bank/corpus/원문_*.md`
  → 없으면 `extract.py`로 먼저 만든다

절차 전문은 `_shared/제안서_교차분석_방법론_v1.0.md`.
**본문 초안 → 조견표 페이지 기입 → 교차분석 → 이식** 순서를 지킨다(조견표가 비어 있으면 분석 불가).

## 작업 중 (필수)
- 하위 작업 하나가 끝날 때마다 즉시 STATE.md 갱신(진행률/방금 끝낸 것/다음/열린 이슈).

- 재사용 가치가 있는 스크립트는 세션이 끝나기 전에 10_work/ 또는 _shared/lib/ 로 내려보낸다(세션 종료 시 소멸).
- 의미 있는 단계마다 git add -A && git commit.
- 되돌릴 수 없는 작업(삭제/덮어쓰기) 전에는 반드시 확인받는다.
- 기준본(사용자가 직접 조정해 저장한 최신본)이 바뀌면 DECISIONS.md와 STATE.md에 명시한다.
- **세션 종료 전 뱅크 환류.** `00_context/뱅크매핑.md`가 있으면(G1=연동)

  **자발적으로는 환류하지 않는다** — 이 항목을 빼먹으면 뱅크는 그 사업 몫만큼 자라지 못한다.
