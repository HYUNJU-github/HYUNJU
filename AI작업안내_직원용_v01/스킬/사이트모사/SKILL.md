# 사이트모사 — 목업에 실제 사이트 톤앤매너 입히기

짐작으로 색을 고르지 않는다. **실제 사이트를 열어서 잰다.** 2026-10-27 윤보경 작업물(충남대 AI 맞춤형 장학 — 학생화면 목업에 with.cnu.ac.kr 스타일 적용)을 실측 비교해서 뽑은 절차다.

## 입력이 없으면 먼저 묻는다
- 목업 파일 경로
- 실제 사이트 URL (로그인 필요하면 사용자에게 직접 로그인해 달라고 요청 — 자격증명 대리 입력 금지)
- 적용 범위: 전체(헤더+색상+폰트+레이아웃+메뉴 구조) 중 일부만인지

## 절차

### 1. 실측 — 추측 금지
브라우저로 실제 사이트를 직접 열어서(Claude_Browser 등) 다음을 `getComputedStyle`/DOM 조회로 측정한다. 스크린샷 픽셀 추출은 2차 수단이고, 가능하면 computed style을 직접 읽는다.
- 색상: 배경·본문글자·보더·버튼·포인트색 hex
- 폰트: font-family, 크기, 굵기 (페이지 제목·섹션 제목·본문 각각)
- 레이아웃 치수: 전체 컨테이너 최대폭, 사이드바 폭, 본문 여백
- 메뉴 체계: 상위메뉴 목록, 하위메뉴 목록, 현재 활성 항목 표시 방식

**어느 화면에서 쟀는지 CSS 주석으로 반드시 남긴다** (예: `/* 실서비스 진로방향설정 화면 실측값 기준 */`). 같은 사이트라도 화면마다 값이 다를 수 있어 출처가 없으면 나중에 검증이 안 된다.

### 2. 외부 리소스 제약 확인
실제 사이트의 폰트 파일 등을 그대로 가져오려 하면 CORS/403으로 막히는 경우가 흔하다. 막히면:
- 같은 서체를 다른 경로(Google Fonts, jsDelivr 등 CDN)에서 **같은 이름 또는 호환 이름으로** 재등록
- 왜 원본을 못 쓰고 우회했는지 CSS 주석으로 남긴다 (예: `/* 폰트 파일 외부 도메인 요청 403 차단 → 동일 서체를 CDN에서 재등록 */`)
- 실측한 폰트가 안 먹혔다고 임의로 다른 폰트로 바꾸지 않는다 — 반드시 "같은 서체의 대체 경로"를 찾는다

### 3. 반복 요소는 컴포넌트화
헤더·사이드바처럼 여러 화면에 똑같이 들어가는 마크업을 화면 수만큼 복붙하지 않는다. Web Component(Shadow DOM) 또는 템플릿 함수로 **한 곳에서만 정의**하고 각 화면은 짧은 커스텀 태그/함수 호출로 삽입한다. 활성 메뉴 등 화면별로 달라지는 값은 속성(attribute)으로 받는다.

### 4. 메뉴/구조를 실제와 맞춘다
실제 사이트의 메뉴 계층(상위→하위, 활성 상태 표시)을 그대로 반영한다. 목업에만 있던 설명용/가짜 메뉴 항목(실제 서비스에 없는 것)은 제거하거나 명확히 "준비 중"으로 표시하고, 실제로 이동 가능한 항목만 클릭되게 한다.

### 5. 기존 인터랙션은 절대 보존
목업에 이미 있는 JS 동작(화면 전환, 토글, 폼 제출 등)은 건드리지 않는다. 작업 전후로 핵심 함수 목록을 뽑아 개수·존재 여부를 대조한다:
```bash
for f in <함수명1> <함수명2> ...; do
  old=$(grep -c "function $f\|window.$f" <원본파일>)
  new=$(grep -c "function $f\|window.$f" <작업후파일>)
  echo "$f: old=$old new=$new"
done
```
개수가 달라지면(특히 줄어들면) 로직이 빠진 것이니 되돌아가서 확인한다.

### 6. 더미 정리
- 실제로 동작하지 않는 링크·버튼은 제거한다
- 클릭 가능한 요소에만 `cursor:pointer` — 안 되는 걸 될 것처럼 보이게 하지 않는다
- 화살표 등 단순 아이콘은 이모지 대신 SVG로, 로고·마스코트는 실제 이미지로 내장한다

### 7. 검증 후 보고
브라우저로 직접 열어 스크린샷·클릭 테스트를 한 뒤, `diff -u <원본> <결과>`로 변경 규모를 확인하고 사용자에게 표로 보고한다 — 무엇이 바뀌었고(색/폰트/레이아웃/구조), 무엇을 그대로 지켰는지(기존 인터랙션)를 나눠서. "아마 이렇게 했을 것"이 아니라 diff·grep으로 확인한 사실만 적는다.

## 하지 말 것
- 실측 없이 "이 정도면 비슷하겠지"로 색상·폰트 결정
- 외부 리소스가 막혔다고 조용히 다른 디자인으로 바꾸기 (대체 경로를 먼저 찾는다)
- 헤더·사이드바를 화면마다 복붙 (한 곳에서 정의해 재사용)
- 작업 후 기존 인터랙션이 되는지 확인 없이 "유지했습니다"라고 보고
