# 직원용 스킬 4개 — 설치와 쓰는 법

> 2026-10-29. 사내 스킬 중 **사업 폴더에서 바로 쓸 수 있고, 우리 서버·볼트에 안 매인 것**만 골라 복사했다.
> 함께 볼 것: 같은 폴더의 `폴더구조와_파일이름.md` · `00_먼저읽기.md`

## 설치 — 한 번만

```bash
# 압축을 푼 폴더 안에서
cp -r ./스킬/* ~/.claude/skills/
```

- Windows 라면 Drive 의 같은 폴더(`share/claude/Projects/_shared/skills-for-staff`) 안의 폴더 4개를
  `C:\Users\<사용자>\.claude\skills\` 밑으로 복사한다. **폴더째** 복사해야 한다(`SKILL.md` 만 옮기면 안 된다).
- 복사한 뒤 **Claude 세션을 새로 연다.** 열려 있던 세션은 스킬 목록을 다시 읽지 않는다.
- 확인: 대화창에 `/` 를 치면 목록에 `eli5` · `검증` · `사이트모사` · `시험의법` 이 보인다.

## 무엇을 하나

| 스킬 | 언제 | 부르는 말 |
|---|---|---|
| `eli5` | 어려운 내용을 **상대 눈높이로** 풀어 설명해야 할 때. 고객 보고, 비개발자 설명 | `/eli5 초등학생 <주제>` · 「우리 팀장한테 설명하듯 풀어 줘」 |
| `검증` | 「이거 맞아?」를 **읽기 전용으로** 판정. 숫자·완료 주장이 근거 있는지 | `/검증 <주장 한 문장>` · 「근거 있어?」 |
| `사이트모사` | 화면 목업(HTML)에 **실제 사이트의 색·폰트·메뉴 구조**를 입힐 때 | `/사이트모사 <목업파일> <실제사이트URL>` |
| `시험의법` | 테스트·점검 **목록을 만들고 닫을 때**. 「다 됐다」를 숫자로 바꾸는 열 가지 법 | `/시험의법` · 「시험 목록 어떻게 세지?」 |

가장 자주 쓰게 되는 둘은 `eli5` 와 `검증` 이다. `검증` 은 파일을 **바꾸지 않으므로** 마음 놓고 불러도 된다.

## 자동으로 불리게 하기 — 프로젝트 `CLAUDE.md` 에 네 줄

스킬은 «이름을 불러야» 돌지 않는다. **설명문이 상황과 맞으면 AI 가 알아서 집는다.**
그래도 확실히 하려면 그 사업 폴더의 `CLAUDE.md` 맨 아래에 아래 블록을 그대로 붙여 넣는다.
`CLAUDE.md` 는 세션이 열릴 때마다 읽히므로, 이 네 줄이 매번 적용된다.

```markdown
## 스킬 — 아래 상황이면 «묻지 말고 먼저» 부른다

| 상황 | 스킬 |
|---|---|
| 내용을 쉽게·상대 눈높이로 풀어 달라(고객·비개발자·보고용) | `eli5` |
| 「맞아?·근거 있어?·정말 다 됐나?」 — 주장·숫자·완료를 확인 | `검증` (읽기 전용) |
| 목업 HTML 에 실제 사이트의 색·폰트·메뉴 구조를 입힌다 | `사이트모사` |
| 시험·점검 «목록»을 만들거나 닫는다 | `시험의법` |

- 부른 스킬 이름을 답 첫 줄에 한 번 적는다 — 무엇을 거쳐 나온 답인지 사람이 알아야 한다.
- 한 번에 하나만 부른다. 상황이 겹치면 더 좁은 쪽을 고른다.
```

붙여 넣은 뒤 **세션을 새로 열어야** 반영된다. 사업 폴더에 `CLAUDE.md` 가 없으면 그 파일부터 만든다.

## 알아 둘 것

- 여기 있는 것은 **사본**이다. 정본은 사내 스킬 저장소에 있고, 고치는 것은 담당자다.
  쓰다가 고칠 데가 보이면 파일을 직접 고치지 말고 담당자에게 알린다 — 사본만 갈라진다.
- 사내 서버·볼트·설계 체인에 매인 스킬(`설계`·`개발`·`관문`·`원격` 등)은 **일부러 뺐다.** 그쪽은 운영 권한과
  승인 절차가 함께 필요하다.
- 스킬은 「대신 해 주는 것」이 아니라 **「같은 순서로 하게 하는 것」**이다. 결과는 늘 사람이 열어서 확인한다.
